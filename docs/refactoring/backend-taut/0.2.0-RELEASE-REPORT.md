## Anti-monitor performance evidence

The validation stages the 952 discovered modules and active configuration into a temporary copy.
Every measured ordinary/shared edit changes source content, and every daemon result is compared
byte-for-byte with `--daemon never`.

| Scenario | Release limit | Observed | Result |
|---|---:|---:|---|
| Cold canonical analysis | 20 s | 9.94–10.03 s | PASS |
| Unchanged disk cache | 3 s | 0.19–0.22 s | PASS |
| Ordinary disk-cache edit | 8 s | 6.91–7.80 s | PASS |
| Cold daemon | 20 s | 9.54 s | PASS |
| Unchanged daemon | 0.5 s | 0.189 s median | PASS |
| Ordinary daemon edit | 2 s | 1.321 s median | PASS |
| Shared daemon edit | 4 s | 2.723 s median | PASS |

Ordinary and shared daemon samples reparsed exactly one module on every edit. The shared target had
610 transitive importers. Thirty unchanged memory checks moved resident RSS from 769,130,496 to
744,325,120 bytes with a 769,146,880-byte peak, so no growth was detected.

The machine-readable evidence is
[`../../performance/anti-monitor-0.2.0.json`](../../performance/anti-monitor-0.2.0.json).

## Release boundary

The anti-monitor policy currently returns canonical exit code 2 because of its existing
exit-relevant indeterminate evaluations. This is not hidden by the accelerated paths: disk cache,
daemon cold/warm/edit/restart/concurrent/memory samples preserve the same stdout, stderr, and exit
code as the non-daemon pipeline.

Rollback remains the documented `pytaut==0.1.*` environment/configuration path in
[`MIGRATION.md`](../../../MIGRATION.md).
